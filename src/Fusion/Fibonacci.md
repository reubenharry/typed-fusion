# Fibonacci fusion category — mathematical specification

This note states the **mathematics** we want `Fusion.Fibonacci` to capture.
Implementation choices (type families, `HomBlocks` packing) are listed only to
mark them as *not* part of the math.

The goal is a faithful, scalable encoding of a (unitary) fusion category,
specialized first to Fibonacci; the same skeleton should later host Ising, etc.

---

## 1. What a fusion category is (the data)

A **ℂ-linear fusion category** $\mathcal{C}$ consists of:

| Data | Meaning |
| --- | --- |
| Objects | A rigid monoidal category, ℂ-linear in each Hom |
| Simples | A finite set $\mathrm{Irr}$ of isomorphism classes of simple objects |
| Unit | $𝟙 \in \mathrm{Irr}$ |
| Fusion | For $a,b \in \mathrm{Irr}$: $a \otimes b \;\simeq\; \bigoplus_{c} N_{ab}^{c}\, c$ with $N_{ab}^{c} \in \mathbb{N}$ |
| Hom | $\mathrm{Hom}(x,y)$ finite-dimensional ℂ-vector spaces; $\mathrm{Hom}(a,b) \cong \delta_{ab}\,\mathbb{C}$ for simples |
| Compose | Bilinear $\circ \colon \mathrm{Hom}(b,c) \times \mathrm{Hom}(a,b) \to \mathrm{Hom}(a,c)$ |
| Duals | Every object has a dual; evaluation / coevaluation satisfy snake identities |
| $F$-symbols | Associator $(a\otimes b)\otimes c \to a\otimes(b\otimes c)$ in a fusion basis |
| $R$-symbols | Braiding $a\otimes b \to b\otimes a$ (if braided / ribbon) |

**Semisimplicity:** every object is isomorphic to a finite direct sum of simples.
Morphisms between sums are **block matrices** of morphisms between simples.

None of: runtime singletons, flat `Vector`, type-level `Norm`/`Stabilize` — those are encodings.

---

## 2. Fibonacci theory (on simples)

**Labels:** $\mathrm{Irr} = \{𝟙,\, \tau\}$.

**Fusion rules** ($N_{ab}^{c}$):

$$
\begin{align*}
𝟙 \otimes x &= x \otimes 𝟙 = x, \\
\tau \otimes \tau &= 𝟙 \oplus \tau.
\end{align*}
$$

As $N$-symbols (only nonzero entries):

$$
N_{𝟙𝟙}^{𝟙} = N_{𝟙\tau}^{\tau} = N_{\tau𝟙}^{\tau} = N_{\tau\tau}^{𝟙} = N_{\tau\tau}^{\tau} = 1.
$$

**Quantum dimensions:** $d_𝟙 = 1$, $d_\tau = \varphi = \frac{1+\sqrt{5}}{2}$, with
$\varphi^2 = \varphi + 1$.

**Global dimension:** $D^2 = d_𝟙^2 + d_\tau^2 = 1 + \varphi^2 = \varphi + 2$
(only needed for some normalizations; not required for basic Hom compose).

This is exactly the data behind `FusionTheory` / `FuseN` for tag `FibTh`.

---

## 3. Objects: trees vs skeleton

Two layers must stay distinct.

### 3.1 Tree objects (syntax)

Formal expressions generated by:

$$
X ::= 𝟙 \mid \tau \mid X \otimes X \mid X \oplus X
$$

Parenthesization of $\otimes$ is part of the tree (needed for $F$-moves).
$\oplus$ is formal direct sum (associative up to canonical iso; we may right-associate).

**Examples:** $\tau\otimes\tau$, $(\tau\otimes\tau)\otimes\tau$, $\tau\otimes(\tau\otimes\tau)$, $𝟙\oplus\tau$.

### 3.2 Skeleton / fused form (semantics)

The **skeletal** monoidal product on isomorphism classes of semisimple objects is:

$$
a \,\hat\otimes\, b \;:=\; \text{the direct sum of simples given by } N_{ab}^{c}.
$$

Extending by bilinearity in $\oplus$ and using the fusion rules on each tensor of simples
yields a **canonical fused form**: a finite multiset (or sorted list) of simples —
equivalently a sum $n_𝟙\cdot 𝟙 \oplus n_\tau\cdot \tau$.

Write $\mathrm{Fuse}(X)$ for that skeletal object associated to a tree $X$.
Then $\mathrm{Fuse}$ is a monoidal functor (up to the usual coherence) from trees to
the skeletal fusion category.

**Math fact used for Hom:**

$$
\mathrm{Hom}_{\mathrm{trees}}(X,Y) \;\cong\; \mathrm{Hom}_{\mathrm{skel}}\bigl(\mathrm{Fuse}(X),\,\mathrm{Fuse}(Y)\bigr)
$$

via choosing fusion isomorphisms (bases of Hom spaces between tensors of simples and
their fused sums). Until those bases are fixed, the iso is canonical only up to
automorphisms of the fused object (products of $\mathrm{U}(N_{ab}^{c})$ phases/bases).

## 4. Hom spaces (the real algebra)

### 4.1 Between simples

$$
\mathrm{Hom}(a,b) =
\begin{cases}
\mathbb{C} & a = b, \\
0 & a \neq b.
\end{cases}
$$

### 4.2 Between skeletal sums

If $X = \bigoplus_i a_i$ and $Y = \bigoplus_j b_j$ with $a_i,b_j$ simple, then

$$
\mathrm{Hom}(X,Y)
\;\cong\;
\bigoplus_{i,j} \mathrm{Hom}(a_i,b_j)
\;\cong\;
\bigoplus_{s \in \mathrm{Irr}}
\mathrm{Mat}_{n_s(Y),\, n_s(X)}(\mathbb{C}),
$$

where $n_s(Z)$ is the multiplicity of simple $s$ in $Z$.

So Hom is a **product of matrix algebras**, one per simple label — not a single
anonymous $\mathbb{C}^n$ until we pick an ordering of basis blocks.

### 4.3 Composition (the mathematical rule)

For $f \colon X \to Y$, $g \colon Y \to Z$, composition is **block matrix multiplication
per simple sector**:

$$
(g \circ f)_s = G_s \, F_s
\qquad (s \in \mathrm{Irr}),
$$

where $F_s \in \mathrm{Mat}_{n_s(Y), n_s(X)}$ and $G_s \in \mathrm{Mat}_{n_s(Z), n_s(Y)}$.

Equivalently, on simple summands:

$$
(g \circ f)_{ik}
=
\sum_j g_{jk}\, f_{ij}
\quad\text{whenever labels match; else }0.
$$

There is **no** special case table of object triples. The only structure constants
for $\circ$ on the skeleton are “matrix multiply in each $\mathrm{Hom}(s,s)$ sector”.

### 4.4 Identity

$\mathrm{id}_X$ is the identity matrix in each sector $s$.

## 5. Duals, cups, caps, snakes

$\tau$ is self-dual. Choose evaluation / coevaluation morphisms

$$
\mathrm{cup} \colon \tau \otimes \tau \to 𝟙,
\qquad
\mathrm{cap} \colon 𝟙 \to \tau \otimes \tau
$$

(so cup = counit $\varepsilon$, cap = unit $\eta$) so that the snake identities
hold in $\mathrm{Hom}(𝟙,𝟙)$ and $\mathrm{Hom}(\tau,\tau)$.

In a unitary pivotal fusion category with standard normalization,

$$
\mathrm{cup} \circ \mathrm{cap} = d_\tau \cdot \mathrm{id}_𝟙 = \varphi \cdot \mathrm{id}_𝟙.
$$

**Important:** $\varphi$ is **not** a weird compose rule. It lives in the
**coefficients of cup/cap** (or in the choice of dual bases). Once those morphisms
are fixed as vectors in the fused Hom spaces, composition is ordinary (rule 4.3).

Under $\mathrm{Fuse}(\tau\otimes\tau) = 𝟙 \oplus \tau$, one has

$$
\mathrm{Hom}(𝟙,\, \tau\otimes\tau)
\cong
\mathrm{Hom}(𝟙,\, 𝟙 \oplus \tau)
\cong
\mathrm{Hom}(𝟙,𝟙)
\cong
\mathbb{C},
$$

so cap is a single scalar in the $𝟙$-channel (the $\tau$-channel component is zero).
Same for cup the other way.

---

## 6. Fusion isomorphisms (fuse / split)

The defining iso of the theory,

$$
\phi_{\tau\tau} \colon \tau \otimes \tau \;\xrightarrow{\;\sim\;}\; 𝟙 \oplus \tau,
$$

is an element of $\mathrm{Hom}(\tau\otimes\tau,\, 𝟙\oplus\tau)$. After identifying both
sides with the same skeletal object via $\mathrm{Fuse}$, a standard choice is

$$
\phi_{\tau\tau} = \mathrm{id}_{𝟙\oplus\tau}
$$

in fused coordinates (split = inverse = same id). Nontriviality of fusion is in
**how tree tensors map into that skeleton**, not in a mysterious 2-vector on End.

Any other choice differs by an automorphism of $𝟙\oplus\tau$ (two nonzero scalars on
the two channels, in the multiplicity-free case).

## 7. $F$-moves and $R$-moves

### 7.1 $F$-symbols

For four simples (here only $\tau$ nontrivial), the associator in a fixed fusion basis
is a unitary matrix $F^{abc}_{d}$ relating the two parenthesizations of
$a\otimes b\otimes c$ with total charge $d$.

**Typed meaning:** `associate @Fib @Tensor @Tau @Tau @Tau` is the associator

$$
(\tau\otimes\tau)\otimes\tau
\longrightarrow
\tau\otimes(\tau\otimes\tau).
$$

Both sides fuse to $𝟙 \oplus \tau \oplus \tau$, so it is an element of
$\mathrm{End}(𝟙\oplus\tau\oplus\tau) \cong \mathbb{C} \times \mathrm{Mat}_2(\mathbb{C})$.

**Extension to general objects** (same $N$-basis as `tensorBlocks`):
`associate` (via `associateBlocks`) $:$ $(a\otimes b)\otimes c\to a\otimes(b\otimes c)$
applies Fibonacci $F$-symbols on fusion trees. Nontrivial only for leaf charges
$\tau\tau\tau$; otherwise the unique allowed reassociation has amplitude $1$.

**τ-sector basis (fixed):** for both associations, `FuseNorm ∘ Norm` yields
`Sum Tau (Sum One Tau)` i.e. simples $[\tau,𝟙,\tau]$ before stabilize. After
sorting Ones-then-Taus, the τ-block indices are:

| index | intermediate of first $\tau\otimes\tau$ |
| --- | --- |
| $0$ | $𝟙$ |
| $1$ | $\tau$ |

**Matrices (Bonderson / standard unitary Fibonacci):**

$$
F^{\tau\tau\tau}_{𝟙} = \varphi^{-1},
\qquad
F^{\tau\tau\tau}_{\tau}
=
\begin{pmatrix}
\varphi^{-1} & \varphi^{-1/2} \\
\varphi^{-1/2} & -\varphi^{-1}
\end{pmatrix}.
$$

Pentagon identity is the check that this basis+matrix choice is coherent (not yet
automated in-tree).

### 7.2 $R$-symbols

Simple-label braiding phases (Bonderson Fibonacci):

$$
R^{𝟙𝟙}_{𝟙}=1,\quad
R^{𝟙τ}_{τ}=R^{τ𝟙}_{τ}=1,\quad
R^{ττ}_{𝟙}=e^{-4\pi i/5},\quad
R^{ττ}_{τ}=e^{3\pi i/5}.
$$

**Extension to general objects** (same $N$-basis as `tensorBlocks`):
`braidBlocks` / `braid` $:$ $a\otimes b\to b\otimes a$ acts by

- **𝟙-sector:** commute $(𝟙\otimes𝟙)$ pairs with $R^{𝟙𝟙}$ and $(τ\otimesτ\to𝟙)$ pairs with $R^{ττ}_{𝟙}$;
- **τ-sector:** $(𝟙\otimesτ)\leftrightarrow(τ\otimes𝟙)$ with unit phases, and $(τ\otimesτ\toτ)$ with $R^{ττ}_{τ}$.

Hexagon identities pair `braid` with `associate`.

$F$ and $R$ must satisfy the pentagon / hexagon equations; that is a **property
to test**, not part of Hom composition.

### 7.3 Status

`associateBlocks` / `braidBlocks` on Mult* $N$-basis (see §7.1–7.2). Remaining:
pentagon/hexagon smoke tests; confirm composite-leg bases against a reference.

## 8. What must be true of any implementation

1. **Compose** on skeletal Homs = per-sector matrix multiply (rule 4.3).
2. **Hom dimensions** = $\sum_s n_s(X)\, n_s(Y)$.
3. **Cup/cap** carry quantum-dimension normalization; compose does not special-case them.
4. **Fuse/split** are (chosen) isos $\tau\otimes\tau \simeq 𝟙\oplus\tau$; after Fuse they may be id.
5. **F/R** are `associate` / `braid` (published matrices on a fixed $N$-basis).
6. Trees remember parenthesization; skeleton forgets it (except via F as a coherent iso).

## 9. Implementation details (not math)

These are encodings. They should be replaceable without changing §1–8.

| Mechanism | Role today | Scalable substitute |
| --- | --- | --- |
| Flat `C (HomDim a b)` | Anonymous coefficient vector | Same vector **plus** documented sector layout, or typed `Hom` as pair of matrices $(M_𝟙, M_\tau)$ |
| `Norm` / `Stabilize` type families | Compute $\mathrm{Fuse}(X)$ | Same math; could be value-level or type-level |
| `composePacked` | Implements §4.3 for Fib’s two sectors | Same algorithm for any multiplicity-free (or multi) theory with $\lvert\mathrm{Irr}\rvert$ sectors |
| `KnownNat` on Mult* | Discharge sizes for `hmatrix-static` | Same; or non-static vectors; or typed block Hom |

**Why the current `packHom` approach feels unscalable:** it case-splits on *object names*
(`One`, `TauTau`, …) instead of on *fused multiplicities* $(n_𝟙,n_\tau)$. Math only
depends on the latter. Object names matter for trees/F/R, not for skeletal compose.

**Design target:**

- Represent a skeletal object as multiplicities (or a sorted list of simples).
- Represent a morphism as sector matrices (or one flat vector with a *single*
  generic layout rule derived from those multiplicities).
- Implement $\circ$ once, generically.
- Attach cups, fuse, F, R as **concrete elements** of those Hom spaces (theory data),
  not as branches of compose.

## 10. Open choices (math-adjacent)

Resolved for the current code:

1. **Hom representation:** sector matrices `HomBlocks` (see §12). Flat `C n` is a derived view only if needed later.
2. **Basis of** $\mathrm{Hom}(\tau\otimes\tau, 𝟙\oplus\tau)$:** fuse/split = id on the fused skeleton $(n_𝟙,n_τ)=(1,1)$.

Still open:

3. **Cup/cap normalization:** @cupCoeff@ on cup ($ε$), $1$ on cap ($η$) (snake $= d_τ$); matches Hom; unitary $\sqrt{\varphi}$ each is an alternative.
4. **Pentagon / hexagon tests** for `associate` / `braid` (§7; basis fixed; coherence not yet checked in code).
5. **Whether trees are objects of the same `Category` instance** as the skeleton, or
   skeletal category + a separate tree language with interpretation $\mathrm{Fuse}$.

## 11. One-line summary

Fibonacci is the fusion category with $\mathrm{Irr}=\{𝟙,\tau\}$, $\tau\otimes\tau=𝟙\oplus\tau$,
$d_\tau=\varphi$; morphisms between semisimple objects are per-simple matrices;
composition is matrix multiply; cups/caps/F/R are elements of Hom, not extra compose rules.

## 12. Implementation: generic sector compose

**Chosen Hom payload** (matches §4.2–4.3):

$$
\mathrm{Hom}(X,Y)
\;\cong\;
\mathrm{Mat}_{n_𝟙(Y),\, n_𝟙(X)}(\mathbb{C})
\times
\mathrm{Mat}_{n_τ(Y),\, n_τ(X)}(\mathbb{C}).
$$

In code (`Fusion.Fibonacci`):

- `MultOne a` / `MultTau a` = multiplicities of $𝟙$ / $τ$ in `CollectSimples (Fuse a)`.
- `HomBlocks n1x ntx n1y nty` holds `blkOne :: M n1y n1x` and `blkTau :: M nty ntx`.
- `Fib a b` wraps `HomBlocks (MultOne a) (MultTau a) (MultOne b) (MultTau b)`.
- `composeBlocks` is the only compose rule: `mul` on each sector. No object-name table.
- `idBlocks` = `(I_{n1}, I_{nτ})`; cups/caps/fuse/split are concrete `HomBlocks`.
- `HomDim a b = MultOne a * MultOne b + MultTau a * MultTau b` (derived).

`Object Fib` is `KnownMult` (= `KnownNat` on both `Mult*`). Compound `KnownNat`
needs for Kronecker / braid / associator are bundled by type families
`NTensorNats` / `AssocNats` → `KnownNTensor` / `KnownAssoc` (and object-level
`KnownTensorMult` / `KnownAssocMult`).

**Fuse as a functor on morphisms:** `fuseMap` is the identity on `HomBlocks`, under `FuseIdemMult`.

**Tensor bifunctor / monoidal Hom:** `MultOne` / `MultTau` are defined $N$-bilinear on `'Tensor` (and additive on `'Sum`), so

$$
n_𝟙(a\otimes b)=n_𝟙(a)n_𝟙(b)+n_τ(a)n_τ(b),\quad
n_τ(a\otimes b)=n_𝟙(a)n_τ(b)+n_τ(a)n_𝟙(b)+n_τ(a)n_τ(b)
$$

definitionally. Then `tensorBlocks` builds

$$
R_𝟙=\mathrm{diag}(F_𝟙\otimes G_𝟙,\; F_τ\otimes G_τ),\qquad
R_τ=\mathrm{diag}(F_𝟙\otimes G_τ,\; F_τ\otimes G_𝟙,\; F_τ\otimes G_τ)
$$

with basis order matching `Norm` distribute (Ones: $𝟙\otimes𝟙$ then $τ\otimesτ\to𝟙$; Taus: $𝟙\otimesτ$, $τ\otimes𝟙$, $τ\otimesτ\toτ$). `bimap` / `first` / `second` call `tensorBlocks`.

**Associative / Monoidal / Braided** (Kmett-shaped, under `Categorical`):

| Class | Fib `Tensor` |
| --- | --- |
| `Monoidal` | `Id = One`; unitors = `idBlocks` |
| `Associative` | `associate`/`disassociate` via `associateBlocks` |
| `Braided` | `braid` via `braidBlocks` |

Not `Symmetric` ($R^2\neq\mathrm{id}$). Pentagon/hexagon untested.

**Optional flat view** (not implemented): row-major `blkOne` then row-major `blkTau` yields a vector of length `HomDim`. One generic flatten/unflatten — never a $4\times 4$ object grid.

**Scalability:** adding a tree object only requires `Fuse` (hence `Mult*`) to typecheck; compose stays unchanged. A second theory (e.g. Ising) needs more sector labels in `HomBlocks`, same compose pattern.
